# Contributing

The rule for `main`: no change can silently alter existing behavior. Either a check fails, or the
PR diff shows exactly what changed and someone approved it. The plan is in
[docs/mvp-plan.md](docs/mvp-plan.md).

## Setup

Node 22 and pnpm (the version pinned in `package.json`, via `corepack enable` or a global install).

```sh
pnpm install
pnpm build          # web app, then a dry-run bundle of the Worker
pnpm dev            # Vite on :5173 with /api proxied to wrangler dev on :8787
```

| Command                | What it does                                                                |
| ---------------------- | --------------------------------------------------------------------------- |
| `pnpm lint`            | ESLint plus repo policy checks (no em dashes, Playwright image in sync)     |
| `pnpm format`          | Prettier (`pnpm format:check` in CI)                                        |
| `pnpm typecheck`       | `tsc` in every package (`@pp/core` src is checked with no DOM or Node)      |
| `pnpm test`            | Vitest: `@pp/core` unit, property and golden (with coverage); web; Worker   |
| `pnpm perf`            | Vitest benchmarks checked against `packages/core/bench/budgets.json`        |
| `pnpm e2e`             | Playwright against local `wrangler dev` (run `pnpm build` first)            |
| `pnpm golden:update`   | Rewrite golden snapshots and `golden-summary.md`                            |
| `pnpm fixtures:record` | Re-record the ORS fixtures with a real key (`ORS_API_KEY` in the env)       |
| `pnpm visual:update`   | Regenerate screenshot baselines in the Linux Playwright container           |
| `pnpm lighthouse`      | Lighthouse accessibility, phone and desktop (run `pnpm build` first)        |
| `pnpm icons`           | Render the app icons in `apps/web/public/icons` from `apps/web/icons/*.svg` |
| `pnpm rollback`        | Roll production back to the previous Worker version (`--dry-run` to check)  |

## Workspace

| Package      | Path            | Purpose                                                               |
| ------------ | --------------- | --------------------------------------------------------------------- |
| `@pp/core`   | `packages/core` | Pure TypeScript, no DOM, no runtime dependencies (a test enforces it) |
| `@pp/web`    | `apps/web`      | React, Vite and Tailwind app                                          |
| `@pp/worker` | `apps/worker`   | Cloudflare Worker `perfect-pace`: static assets plus `/api/*`         |
| `@pp/e2e`    | `e2e`           | Playwright suites                                                     |

`apps/worker/worker-configuration.d.ts` is generated by `pnpm --filter @pp/worker cf-typegen`;
rerun it after changing `wrangler.jsonc` (CI checks it is current).

## Test layers

| Layer               | Tool                                   | Where                                           | Runs                            |
| ------------------- | -------------------------------------- | ----------------------------------------------- | ------------------------------- |
| Unit and property   | Vitest                                 | `packages/core/test/*.test.ts`                  | Every PR                        |
| Web unit            | Vitest (store, sheet math, worker RPC) | `apps/web/test/*.test.ts`                       | Every PR                        |
| Golden snapshots    | Vitest                                 | `packages/core/test/golden-cases.ts`            | Every PR                        |
| Worker integration  | Vitest + `@cloudflare/vitest-plugin`   | `apps/worker/test`                              | Every PR                        |
| Performance budgets | Vitest bench, Playwright `performance` | `packages/core/bench`, `e2e/tests/perf.spec.ts` | Every PR (over budget fails CI) |
| E2E                 | Playwright (desktop, iPhone, Pixel)    | `e2e/tests`                                     | Every PR, against the preview   |
| Visual regression   | Playwright `toHaveScreenshot`          | `e2e/tests/visual.spec.ts`                      | Every PR                        |
| Accessibility       | axe in Playwright                      | `e2e/tests/a11y.spec.ts`                        | Every PR                        |
| Accessibility score | Lighthouse (at least 95)               | `e2e/scripts/lighthouse.mjs`                    | Every PR                        |
| PWA                 | Playwright, service worker on          | `e2e/tests/pwa.spec.ts`                         | Every PR                        |
| Live smoke          | Playwright `@smoke` and `@live`        | `e2e/tests`                                     | Nightly and after each deploy   |

Rules of thumb:

- `@pp/core` has a 90% line and branch coverage floor. The UI relies on E2E tests instead.
- Randomized tests always use a fixed seed (`packages/core/test/support/rng.ts`) and print it on failure.
- Fixtures are committed and never fetched at test time. Only `@live` tests (nightly) touch the network.
  E2E serves map and DEM tiles from fixtures (`e2e/support/app.ts`), and answers `/api/route` from the
  ORS fixtures through the Worker's own parser (`e2e/support/draw.ts`), so drawing tests need no key.
  E2E tests open the app with `openApp` (`e2e/support/app.ts`), which serves the basemap TileJSON from
  `e2e/fixtures/openfreemap` and answers every tile and glyph request with an empty response.
- Every bug fix starts with a failing E2E or golden test that reproduces it.
- Tag tests that are safe against production `@smoke`, tests that need real third-party services `@live`.

## Golden snapshots

Each case in `packages/core/test/golden-cases.ts` writes `packages/core/test/golden/<name>.json`, and
all of them roll up into `golden-summary.md` for a readable diff. Round every number with the
stated precision in `test/support/precision.ts` (1 m distance, 0.1 m elevation, 0.1 s pace).

`pnpm test` fails when a snapshot is stale, missing or orphaned, or the summary is out of date. To
accept a change on purpose:

```sh
pnpm golden:update
git diff packages/core/test/golden   # review it
```

The PR description must say why the outputs changed.

## Visual baselines

Baselines live in `e2e/tests/__screenshots__/<project>/` and are only ever generated in the
official Linux Playwright container (`mcr.microsoft.com/playwright:v<version>-noble`), the same
image the CI `e2e` job runs in, so they match pixel for pixel. Local `pnpm e2e` runs skip screenshot
assertions (set `PP_VISUAL=1` to force them).

```sh
pnpm visual:update        # with Docker: regenerates baselines locally in the container
pnpm visual:update --ci   # without Docker: labels your pushed branch's PR `visual-update`, which
                          # runs the "Visual baselines" workflow, and downloads its output here
```

Commit the new PNGs and give the reason in the PR description. A missing baseline fails CI. When
bumping `@playwright/test`, bump the container image tags in `.github/workflows` to match (`pnpm
lint` checks) and regenerate the baselines.

## Performance budgets

Every benchmark in `packages/core/bench/*.bench.ts` needs an entry in `bench/budgets.json` (its
`file > group > name` key and a `maxMedianMs`), and every budget needs a benchmark. Browser budgets
read `performance` marks in `e2e/tests/perf.spec.ts`, and timing budgets that must not share the CPU
with other tests run in their own projects, one after another once the others finish: the 50k-point
course load (`load-perf`, `e2e/tests/load-perf.spec.ts`), then the marathon plan recompute
(`plan-perf`, `e2e/tests/plan-perf.spec.ts`). Raise a budget only with a reason in the PR.

## Flaky tests

No blanket retries. Playwright gets one retry in CI, and a test that passes only on retry shows up
as flaky in the report. Within the same week, either fix it or tag it `@quarantine` and link an
issue. Quarantined tests still run in CI in a separate, non-blocking step.

## CI and deploys

| Workflow           | Trigger                          | What it does                                                             |
| ------------------ | -------------------------------- | ------------------------------------------------------------------------ |
| `CI`               | every PR                         | `verify`, `perf`, `preview` (alias `pr-<n>`), `e2e`, `lighthouse`        |
| `Deploy`           | push to `main`                   | deploy production, smoke test it, roll back and open an issue on failure |
| `Nightly`          | 07:17 UTC daily                  | live smoke against production, full E2E on Chromium, Firefox and WebKit  |
| `Visual baselines` | `visual-update` PR label, manual | regenerate screenshot baselines (used by `pnpm visual:update --ci`)      |

The required checks on `main` are `verify`, `perf`, `preview`, `e2e` and `lighthouse`, with an
up-to-date branch. `e2e` includes the axe checks (`a11y.spec.ts`, every key screen in both themes,
including offline and keyboard drawing) and the PWA suite; `lighthouse` fails below an
accessibility score of 95. Branch protection needs GitHub Pro on a private repository, so until
then these are required by convention: every job hard-fails, and nothing merges red. Playwright traces, videos and screenshot diffs are uploaded as artifacts when a test fails.

Deploys need two repository secrets: `CLOUDFLARE_API_TOKEN` (a token from the "Edit Cloudflare
Workers" template) and `CLOUDFLARE_ACCOUNT_ID`. Without them the `preview` job skips the deploy and
`e2e` runs against a local `wrangler dev` instead, and `Deploy` skips.

A third, optional secret, `ORS_API_KEY`, is the OpenRouteService key `/api/route` uses (see
[Routing](#routing)). `Deploy` uploads it to the Worker with each production version, previews
inherit it, and `Nightly` runs the live routing test only when it is set. Without it nothing fails:
`/api/route` answers `503 not_configured` and the live routing test is skipped with a warning.

To exercise the rollback path without touching production traffic, run the `Deploy` workflow by
hand with "force smoke failure" and "dry run" checked, or locally:

```sh
DRY_RUN=1 PP_FORCE_SMOKE_FAIL=1 bash scripts/post-deploy-smoke.sh <production-url> <live-version> <previous-version>
```

## PWA and offline

The app is installable and works offline for uploaded GPX courses. The pieces:

- **Manifest and icons:** `apps/web/public/manifest.webmanifest`, and PNG icons rendered from the
  SVG sources in `apps/web/icons` (`pnpm icons`, which uses the E2E suite's Chromium; commit the
  PNGs). `favicon.svg` is a copy of `icons/icon.svg`.
- **Service worker:** `apps/web/src/sw/sw.ts`, built to `/sw.js` by `precachePlugin`
  (`apps/web/precache-plugin.ts`), which fills in the precache list (every built and public file,
  plus `/`) and a version hash of their contents. The routing rules are in `src/sw/policy.ts`
  (unit tested in `apps/web/test/sw-policy.test.ts`):
  - Hashed files and icons: from the version's precache first.
  - Navigations: network first, so an online reload always gets the latest build; the cached shell
    answers when offline or after 4 s. Share links live in the hash, so they are navigations to `/`.
  - Terrarium DEM tiles: a least recently used cache of at most 256 tiles (about 25 MB).
  - Never cached: `/api/*`, non-GET requests, the basemap, and files not in the precache (the
    Worker answers a missing `/assets/` file with the app's HTML, which must never be kept).
- **Updates:** a new version installs, takes over at once, and keeps the previous build's cache so
  an open page can still load its lazy chunks. The page's status line (under the name) then offers
  a reload. Long-open pages check for a new version at most hourly when they come back into view.
- **Offline:** the status line says "Offline", drawing is off (legs need the routing service, and
  the basemap is not cached) and the panel says why, while uploads, plans and exports still work.
- **Headers:** `apps/web/public/_headers` (read by Workers static assets) serves `sw.js` and the
  manifest with `Cache-Control: no-cache` and hashed assets as immutable.
- **Tests:** E2E runs with service workers blocked (`playwright.config.ts`), since one would answer
  requests the tests stub. `e2e/tests/pwa.spec.ts` turns them on: manifest and icons, Chrome's
  installability check (`Page.getInstallabilityErrors`; Lighthouse 12 removed its PWA audits),
  precache contents, network-first reloads, the update prompt, an offline reload of an uploaded
  course with terrain tiles from the cache (`context.setOffline` with every stub removed), and the
  tile cache's bound. Safe-area insets are simulated with `Emulation.setSafeAreaInsetsOverride`.
- **Real phone:** see [docs/real-phone-checklist.md](docs/real-phone-checklist.md).

## Routing

`POST /api/route` (in `apps/worker/src/route.ts`) routes one leg on foot through hosted
OpenRouteService, holding the key server side. The request, response and error codes are the wire
contract in `packages/core/src/routing.ts`, with the `RoutingProvider` interface and
`httpRoutingProvider`, the client for it.

- **Key:** get a free one at <https://openrouteservice.org/dev/#/signup> (2,000 directions requests
  a day, 40 a minute). Set it as the `ORS_API_KEY` repository secret (`gh secret set ORS_API_KEY`),
  and the next deploy uploads it; or set it directly with
  `pnpm --filter @pp/worker exec wrangler secret put ORS_API_KEY`. For `pnpm dev`, put
  `ORS_API_KEY=...` in `apps/worker/.dev.vars` (gitignored).
- **Cache:** successful legs are cached for a week with the Cache API, keyed by profile and
  coordinates rounded to 5 decimals (about 1 m). The Cache API does nothing on `*.workers.dev`, so
  this only takes effect on a custom domain.
- **Rate limit:** 20 upstream (uncached) requests per client IP per minute, with the Workers Rate
  Limiting binding `ROUTE_RATE_LIMITER` in `wrangler.jsonc`. A counter in Worker memory would be
  per isolate, and so easy to exceed; the binding is shared within each Cloudflare location (and
  eventually consistent, so bursts can overshoot slightly). It does not cap the shared daily quota;
  ORS answers `upstream_rate_limited` once that is used up.
- **Fixtures:** the Worker tests replay `apps/worker/test/fixtures/ors/` and never call ORS. The
  committed files are synthetic until someone runs `ORS_API_KEY=... pnpm fixtures:record` (see the
  README there).

## Dependencies

Renovate opens one grouped PR a week for minor and patch updates, which auto-merges when green.
Major updates, Playwright (baselines may need regenerating) and anything failing need review.
Prefer a few lines of code over a new dependency, and keep `@pp/core` free of runtime dependencies.
